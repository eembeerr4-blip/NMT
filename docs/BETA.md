# NMT Academy — візуальна бета

## Для тестувальника

Відкрийте http://127.0.0.1:3100. Це окрема тестова копія із синтетичними даними. Основний сайт на3000 не оновлювався.

Тестові профілі: `student_a`, `student_b`, `qa_editor`, `qa_admin`, `owner`. Пароль тільки для цих QA-профілів: `Nmt-Ui-QA-Only-2026`. Не використовуйте його для справжнього облікового запису.

Почніть із «Предмети» → «Математика» → QA-тема → «Відкрити урок». Урок має вкладки «Відео», «Конспект», «Приклади», «Практика». Відсутність відео не заважає читанню. «Матеріал готується» означає, що починати урок ще немає з чого.

У тесті відповіді зберігаються автоматично. Перевіряйте напис «Відповіді збережено». Якщо мережа недоступна, залишайте вкладку відкритою та повторіть збереження. Порядок у завданні на послідовність потрібно змінити або підтвердити. Завершення тесту потребує підтвердження; результат не є вигаданим рейтинговим балом НМТ.

«Налаштування» → «Навчання»: четвертий предмет, денний ліміт, навчальні дні та загальна ціль. «Тема інтерфейсу»: світла/темна/системна. Особисті перенесення та виконані заняття зберігаються під час перебудови автоплану.

Адміністратор відкриває панель через меню профілю. «Банк запитань» — навчальний контент; «Навчальні заняття» — розклад. У «Тести» можна створити чернетку набору, опублікувати або архівувати. Набір зі спробами захищений від редагування: створіть нову версію. Архів не видаляє історію.

Як повідомити про проблему: URL, роль, кроки, очікуваний і фактичний результат, ширина екрана, знімок. Паролі, cookie й резервні копії не надсилайте. Використовуйте [10 сценаріїв](BETA-CHECKLIST.md).

## Для владельца: запуск и границы

Проверяемый код находится в `D:/Вайб-кодинг/nmt-beta`, последовательные ветки `beta/*`. Исходный проект `C:/Users/User/nmt-academy` не переключался и не получал эти изменения через merge. Рабочий порт3000 не останавливался.

В текущем локальном окружении:

```powershell
Set-Location -LiteralPath 'D:/Вайб-кодинг/nmt-beta'
./audit/qa-server.ps1 Status
./audit/qa-server.ps1 Start # только если Status подтвердил остановку
```

`audit/` — локальные материалы проверки, по заданию не входят в коммиты. Помощник запуска задаёт абсолютный QA DATABASE_URL, порт3100 и `SESSION_COOKIE_SECURE=false` только для процесса. Перед новой сборкой остановите оба QA-сервера: на Windows Prisma generate не может заменить DLL, занятую запущенным сервером. Рабочий сервер3000 не трогать.

Чистая дополнительная QA-база и сервер3101:

```powershell
./audit/fresh-runtime.ps1 Prepare # отказывается перезаписывать существующий файл
./audit/fresh-runtime.ps1 Start
npx playwright test --config playwright.fresh.config.ts
./audit/fresh-runtime.ps1 Stop
```

Для обычного регрессионного набора используйте только `playwright.beta.config.ts`. Старый `playwright.config.ts` запускает сервер3000 и не подходит для этой проверки. `npm test` выполняют с QA DATABASE_URL: DB-наборы самостоятельно создают временные базы; opt-in аудит рабочей базы выключен. Итоги, SHA и ограничения находятся в `audit/PROGRESS.md` и `audit/reports/`.

### Сброс только QA

Проще создать новый тестовый профиль: его личные данные будут пустыми. Для полного нового прогона3101 сначала остановите его, затем сохраните все файлы SQLite в архив, не удаляя их:

```powershell
Set-Location -LiteralPath 'D:/Вайб-кодинг/nmt-beta'
./audit/fresh-runtime.ps1 Stop
$qaDirectory=(Resolve-Path -LiteralPath './audit/tests').Path
$qaArchive=Join-Path $qaDirectory ('archive-'+(Get-Date -Format 'yyyyMMdd-HHmmss'))
$null=New-Item -ItemType Directory -Path $qaArchive
foreach($qaSuffix in @('','-wal','-shm')) {
  $qaFile=[IO.Path]::GetFullPath((Join-Path $qaDirectory ('beta-fresh.db'+$qaSuffix)))
  if([IO.Path]::GetDirectoryName($qaFile) -ne $qaDirectory){throw 'Путь вне QA'}
  if(Test-Path -LiteralPath $qaFile){Move-Item -LiteralPath $qaFile -Destination $qaArchive}
}
./audit/fresh-runtime.ps1 Prepare
```

Эти команды относятся только к `audit/tests/beta-fresh.db`. Не подставляйте рабочую базу и не используйте `db:reset:auth`, `migrate reset` или `db push`.

### Телефон, резервные копии и ограничения

Текущий сервер слушает127.0.0.1 и доступен только на компьютере. Для телефона нужен отдельный QA-запуск на локальном IP через `next start --hostname 0.0.0.0 --port 3102`, с абсолютным QA DATABASE_URL и разрешением локального соединения в Windows. Предпочтителен HTTPS. Для временного HTTP на доверенной домашней сети требуется процессный `SESSION_COOKIE_SECURE=false`: cookie передаётся без транспортного шифрования. Это не настройка публичного сервера; `.env` не менять, роутер наружу не открывать.

JSON backup доступен владельцу и содержит `passwordHash`. Храните его приватно, не отправляйте в чат/репозиторий. Включённый WAL не позволяет безопасно копировать только открытый файл `.db`; используйте `VACUUM INTO` или согласованный механизм backup. Текущий JSON export читает таблицы через Prisma, но консистентный snapshot под конкурентной записью остаётся A11 — отдельным техдолгом.

Учебные материалы, публичный хостинг, AI и интеграция новой персонализации не входили в запуск. C10 (сохранение незавершённых шагов onboarding) отложен. A12 (IP/distributed throttle) и A13 (layout sync/N+1) не исправлялись. В рабочей истории ожидает отдельного решения владельца миграция nickname_case_insensitive; на QA она применена при создании новой базы. Слияние веток, миграция рабочей базы и выпуск беты выполняются только отдельным решением владельца.
