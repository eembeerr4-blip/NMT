## NMT-001. После входа переход к предметам возвращал на /login

Приоритет: высокий. Статус: исправлено, результат подтверждён браузером.

### Воспроизведение до изменения
1. Пользователь вручную входит в существующий профиль.
2. Открывается главная / с именем профиля и планом.
3. Нажатие «Предмети», ссылка /subjects.
4. Вместо предметов открывается /login.
5. После повторного ручного входа ошибка воспроизводится снова.

Фактическое назначение возврата — форма входа /login, а не главная /.
В доступном журнале браузера при первой проверке не было ошибок и предупреждений. Это не доказывает отсутствие ошибок сервера или HTTP.

### Причина
В src/server/session.ts атрибут secure у cookie nmt_user вычислялся только через NODE_ENV === "production". Рабочий сервер был запущен через next start -p 3000, а пользователь открывает сайт по HTTP на IP-адресе локальной сети.
Cookie с атрибутом Secure предназначена для HTTPS. По этому HTTP-адресу браузер не сохранял рабочий вход. Главная могла появиться в ответе Server Action после входа, но следующий запрос не приносил cookie и защита маршрута возвращала на /login.

### Изменения
- Добавлен src/lib/session-cookie.ts: явная настройка SESSION_COOKIE_SECURE=true/false; без настройки production по-прежнему требует HTTPS.
- src/server/session.ts использует эту настройку.
- В локальном .env установлено SESSION_COOKIE_SECURE=false для существующего HTTP-сайта.
- Добавлены описание в README.md и закомментированный пример в .env.example.
- Добавлены пять тестов настройки cookie, включая безопасное значение по умолчанию и отказ при опечатке.
- Приложение пересобрано и запущено на прежнем адресе.

Проверка пароля, случайный токен сессии, хранение его хеша в базе, httpOnly, sameSite=lax и проверка пользователя на сервере сохранены. При переходе этого сайта на HTTPS нужно убрать локальное false или установить true.

### Проверка после изменения
- Пользователь повторно вошёл вручную.
- Главная → Предмети открывает /subjects.
- Обновление /subjects сохраняет вход и содержимое.
- Переходы по всем основным разделам меню больше не возвращают на /login.
- Математика → Лінійні рівняння → Відкрити урок открывает соответствующие страницы.
- Назад/вперёд между темой и уроком сохраняют вход.
- После следующей сборки и перезапуска основная вкладка по-прежнему открыла урок без повторного входа.

## NMT-002. Неверный вход не показывал причину отказа

Приоритет: средний. Статус: исправлено, результат подтверждён браузером.

### Воспроизведение
В отдельной вкладке /login введены заведомо несуществующий диагностический никнейм и тестовый пароль. После отправки форма очищалась, сообщения об ошибке не было.

### Причина
Функция login возвращала { ok: false, error: "Невірний нікнейм або пароль." }, но обработчик формы в src/app/login/page.tsx игнорировал возвращаемое значение.

### Изменения
- Добавлен src/components/login-form.tsx с useActionState.
- Ошибка сервера выводится в элементе role=alert.
- Кнопка блокируется во время отправки, показывается состояние «Вхід…».
- Поля имеют понятные доступные имена. Существовавшая параллельная правка подписи поля пароля сохранена при переносе полей в компонент.
- Страница /login передаёт результат серверного входа в форму.

### Проверка
Та же попытка с несуществующим пользователем теперь показывает «Невірний нікнейм або пароль.». Основная авторизованная вкладка продолжает работать.
Подтверждение: login-error-fixed.png.
