# NMT Academy — перевірка в Google Chrome

Дата: 18 жовтня 2026. Перевірений commit: `a37d8cb27642ab8fe1982aaf5810f42e165856a5`.

## Висновок

Основний навчальний шлях працює у звичайних умовах: вхід, предмет, тема, урок, запуск практики, відповіді, ручне завершення, результат, журнал помилок, нотатки та повторний вхід. Загальне мимовільне повернення на головну в перевірених переходах не відтворилося.

Проте приймання **не пройдено**: підтверджено втрату свіжої відповіді після швидкого оновлення, часткове збереження при збої завершення тесту, відсутність повідомлення про збій таймера, зникнення перенесеного власного заняття, відсутній редактор питання для EDITOR та помилки збереження трьох типів питань.

Це виконаний пріоритетний Chrome-прохід, **не виконані всі 504 комбінації** початкової матриці. Повна негативна перевірка кожної серверної операції, усіх ролей на кожному маршруті та всіх станів ще потрібна. Наведені нижче PASS стосуються тільки конкретних виконаних підсценаріїв.

## Середовище і межі

- Справжній Google Chrome, керування через браузерний інструмент; не Playwright test runner і не симуляція за кодом.
- Окремий QA-сайт `http://127.0.0.1:3001`, синтетична база `audit/chrome-20261018/qa.db`. Робочий сайт — `http://localhost:3000`; інший hostname відокремлює cookie, одного іншого порту було б недостатньо.
- Вхід виконано під STUDENT_A, STUDENT_B, EDITOR, ADMIN, OWNER; анонімний сценарій — після виходу. П'ять облікових записів плюс ANON = шість ідентичностей.
- База створена з нуля п'ятьма поточними міграціями. Дані, паролі та ключі робочої бази не копіювалися. Наявні сесії користувача на localhost не підмінялися.
- Код скопійований із чистого tracked-дерева зазначеного SHA. У копії налаштовано лише `turbopack.root` для підключення встановлених залежностей. QA використовує dev/Turbopack, а не production build. Production/LAN/Secure-cookie поведінка цим проходом не підтверджується.
- Перший запуск QA через webpack не застосовував Tailwind-правило з turbopack-конфігурації; цей запуск відкинуто для візуальних висновків. Подальші перевірки проведені після перезапуску з Turbopack.
- Перевірено 1440×900 та 390×844; додатково головну на 768 і 1920 px. Виміряно DOM overflow, зроблено знімки, перевірено меню. Це не повний аудит контрасту, всіх breakpoint або screen reader.
- Ознак Dark Reader у DOM перевірених екранів не знайдено. Вимкнення всіх розширень на рівні налаштувань Chrome не підтверджене.
- Через обмеження мережі QA не зміг завантажити Google Font Manrope; використано fallback. Це обмеження середовища, не доведена помилка робочого сайту. Реальне відтворення YouTube не перевірено.
- Вихідні файли застосунку та робоча база для тестів не змінювалися. Усі fixtures, тригер контрольованого збою та результати знаходяться всередині QA. Тестовий тригер після перевірки видалено. Виправлень продукту не вносив.

## Підтверджені проблеми

### C01 / A04 — P1: швидке оновлення стирає щойно введену відповідь

STUDENT_A → `/tests/qa-attempt-a` → ввести `3` у перше числове питання → відразу reload.

Факт: поле знову порожнє, навігація показує «без відповіді», хоча текст «Відповіді збережено автоматично» присутній. Це не вимірювання точної кількості мілісекунд, але безпосередньо відтворена послідовність вводу й миттєвого reload. Після звичайного збереження з паузою відповідь `3` відновлюється — цей контроль пройдено на новій практиці.

Причина узгоджується з `src/components/test-runner.tsx:32` та `:55`: стан береться із серверної чернетки, локальна чернетка не відновлюється; запис на сервер відкладено на 450 мс. Потрібні відновлення локальної чернетки та чесний індикатор pending/saved/error.

Доказ: `screens/FAIL-A04-rapid-reload.png`; контроль — `screens/draft-restored-after-save.png`.

### C02 / A03 — P1: завершення тесту не відкочується при помилці посередині

Лише QA: створено окремий timed test і тригер SQLite, який відхиляє INSERT другої відповіді **лише** для `qa-fault-timeout-a`. У Chrome введено три правильні відповіді й дочекалися завершення таймера.

Факт після помилки: `TestAttempt.status=IN_PROGRESS`, `finishedAt=null`, але перша відповідь уже записана в `Answer`. Відкату всіх змін немає. Це runtime-підтвердження часткового запису, а не доказ дублювання XP у двох вкладках: concurrency-сценарій окремо не виконувався.

Потрібна транзакція завершення та ідемпотентний захист повторного виклику. Джерело: `src/server/actions.ts:464`, окремі delete/create/наступні записи.

Доказ: `fault-state.json`, `fault.cjs`, `screens/FAIL-timer-write-error.png`.

### C03 / A05 — P1: збій автозавершення не показується учневі

Той самий контрольований збій. Chrome лишився на формі тесту з таймером `0:00`, без повідомлення про помилку; автоматично результат не з'явився. Після видалення тригера автоматичного повторення не сталося. Натискання звичайної кнопки «Завершити» та підтвердження успішно дали `3/3`.

Потрібно обробляти `result.ok`, показувати помилку і явний retry, зберігати чернетку до підтвердженого успіху. Видалення localStorage та unhandled rejection під час цього проходу окремо не інструментувалися; щодо них не заявляємо runtime PASS/FAIL.

Доказ: `screens/FAIL-timer-write-error.png`, `screens/fault-manual-recovery.png`; код `src/components/test-runner.tsx:71`.

### C04 — P1, нова знахідка: перенесене власне заняття зникає

STUDENT_A → календар → додати «QA Chrome власне заняття» на 18.10.2026 без предмета → «Розпочати» → перенести на 20.10.2026 → відкрити 20.10.

Факт: нове заняття відсутнє у видимому плані. У QA-базі оригінал має `MOVED`, а створена на 20.10 копія — `DROPPED`, `templateKey=moved-…`. Це не втрачений HTTP-запит: сервер зафіксував успішний `moveTask`, а обидва записи є в базі.

Причина: `src/server/sync.ts:57` скасовує кожне PLANNED заняття з templateKey, якого немає серед поточних автослотів. Перенесені й власні ключі не є ключами автоплану. `createCustomTask` теж присвоює `custom-…`, тому окремо перевірити збереження всіх майбутніх власних занять.

Виправлення: відрізняти походження заняття; синхронізація може скасовувати лише породжені нею автослоти. Regression: custom → reload; move → reload; зміна ліміту/днів не стирає custom/moved та DONE.

Доказ: `screens/calendar-custom-created.png`, `screens/calendar-task-moved.png`, `final-db-check.json`.

### C05 / A01 — P1: EDITOR не може відкрити редагування питання

EDITOR → `/editor/questions` → «Редагувати» числове невикористане питання. Посилання відкриває `/editor/questions/qa-unused-NUMERIC`, де показано «Сторінку не знайдено»; серверний GET повернув 404.

Потрібен справжній detail route редактора з відповідними серверними правами та поверненням до `/editor/questions`, без послаблення admin guard.

Доказ: `screens/editor-question-bank.png`, `screens/FAIL-A01-editor-edit.png`.

### C06 / A02 — P1: збереження трьох типів питань ламається

ADMIN → невикористане SINGLE_CHOICE / MATCHING / SEQUENCE → змінити тільки умову, не редагуючи правильну відповідь → «Зберегти зміни».

Факт для кожного: «Не вдалося виконати дію», редагування не завершується. Контрольний NUMERIC зберігся і повернув до банку, статус став «Очікує перевірки». Використані питання не змінювалися.

Дані fixture містили збережені option IDs; форма передає їх як correctAnswer, але не зберігає IDs варіантів. Виправити перетворення ключів/id на межі редактора. Generic повідомлення додатково не пояснює адміністратору, що зробити.

Доказ: `screens/FAIL-A02-single-choice.png`, `screens/FAIL-A02-matching.png`, `screens/FAIL-A02-sequence.png`, `screens/numeric-edit-success.png`.

### C07 / A09 — P2: урок із теорією без питань не можна завершити

STUDENT_A → `/learn/qa-empty` → «Практика». Сайт правильно не запускає порожній оцінюваний тест, але завершення недоступне навіть після читання наявного конспекту. Прапорця «Я опрацював конспект» немає.

Доказ: `screens/lesson-no-questions.png`. Потрібно узгодити продуктове правило завершення теоретичного уроку й відобразити підтриманий backend-сценарій.

### C08 / A06 — P2: відмова зміни предмета мовчазна

У навчальних налаштуваннях обрати географію й натиснути «Змінити предмет» без прапорця підтвердження. Предмет залишається біологією, але повідомлення про причину відмови відсутнє, форма скидає вибір. Після повторного вибору географії та прапорця зміна проходить. У базі рівно один активний elective; історичний математичний результат збережений.

Доказ: `screens/FAIL-elective-no-confirm-no-feedback.png`, `screens/elective-change-result.png`, `final-db-check.json`. Частковий збій усередині changeElective не ін'єктувався; атомарність цієї операції залишається неперевіреною.

### C09 / A14 — P2: анонімний API повертає сторінку входу

Після виходу перехід до `/api/export/backup` привів на `/login` з HTML-формою. Очікуваний для API JSON 401 не отримано. STUDENT/EDITOR/ADMIN із чинною сесією натомість отримують JSON-відмову повного backup, серверний статус 403. Некоректна cookie та POST AI API тут не перевірені.

### C10 / A08 — P2: майстер onboarding не відновлюється

ANON → `/onboarding` → «Розпочати» → ввести тестове ім'я → reload. Повернення на початковий екран «Розпочати», введений стан відсутній. Новий профіль через UI не створювався. Окремі baseline/goals не входять до перевіреного SHA за кодовим аудитом; наскрізне приймання всього персоналізованого wizard лишається BLOCKED_BY_A08.

Доказ: `screens/onboarding-start.png`, `screens/onboarding-reload-loses-step.png`.

## Пріоритет наступних робіт

1. **Надійність тестів:** C01–C03, транзакція, повторне завершення, відновлення чернетки, правдивий статус збереження. Потім повторити quick reload / fault / дві вкладки.
2. **Календар:** C04, захист custom/moved від автоплану; регресія зміни днів, навантаження, предмета й reload.
3. **Редактор питань:** C05–C06; повний editable round-trip всіх типів без втрати ключів, guard EDITOR і правильні return routes.
4. **Завершення уроку й повідомлення:** C07–C08; читабельна відмова й теорія без практики.
5. **Після цього:** персоналізований onboarding C10, API-контракт C09 і непокриті негативні перевірки ownership/restore/concurrency/відео.

Списки не впали, у «Мої тести» є реальний незавершений тест із посиланням «Продовжити». Доказ — `supplementary-smoke.json`. Відкриття сторінки не означає виконання всіх її кнопок.
