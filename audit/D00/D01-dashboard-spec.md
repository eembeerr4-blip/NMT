# D01 — точное ТЗ на главную ученика

**Статус: только спецификация. Реализация не начата.**

## 1. Цель и исходная версия

Воспроизвести композицию экрана 1 «Головна» и её мобильную адаптацию из экрана 16 утверждённого `reference/approved-16-screens.png`, используя настоящие данные и действующие маршруты.

Предлагаемая основа — `beta/06-visual-beta@9ef3c662`, новый изолированный worktree/ветка `codex/d01-dashboard` после подтверждения владельца. Не выполнять merge в исходную рабочую ветку. Если владелец выбирает другой SHA, сначала сверить зависимости и обновить это ТЗ.

Выпуск D01 не содержит новую регистрацию, уведомления, внешний каталог тестов, CMS файлов, AI, XP или магазин наград. Prisma, роли, проверки доступа и алгоритмы плана не меняются.

## 2. Визуальная композиция desktop

Следовать порядку и отношению блоков эталона:

```text
┌ sidebar ┬ header: поиск                          профиль / тема ┐
│         ├ приветствие + «Продовжити навчання» ┬ «Мій прогрес»   │
│         │ подпись + «Весь мій план»           │ компактный график│
│         ├ четыре компактные карточки активных предметов         │
│         ├ «План на сьогодні»                  ┬ «Найближчі      │
│         │ реальные строки занятий            │ пробники»       │
└─────────┴─────────────────────────────────────┴─────────────────┘
```

- Основной desktop: 1440×900. Рабочая стартовая спецификация: sidebar 240px, header 64px, внутренние отступы 24px, gap 16px; ≥1280px верхняя область ~58/42, нижняя ~62/38; четыре subject cards в один ряд.
- Это проектные размеры адаптации, а не якобы измеренные исходные размеры уменьшенного коллажа. После первого рендера сравнить пропорции с экраном 1 и скорректировать, сохранив текстовую читаемость.
- Приветствие 26–28px semibold, обычный текст 14px, meta 12px; карточки имеют плотные внутренние отступы 14–16px. Общая высота главных трёх рядов ориентировочно 650–740px при 1440×900, если данных мало/умеренно. Не сжимать произвольное количество строк до нечитаемого размера ради запрета скролла.
- Синий активный пункт, глубокие тёмные поверхности, тонкая граница, локальный cyan/blue glow, предметные акценты; белая тема с теми же структурами и читаемыми контрастами. Не вставлять растровый экран вместо HTML.
- Sidebar содержит рабочие ссылки, текущее состояние; недостающие «Повідомлення»/«Статистика» нельзя добавлять пустыми пунктами. Подробная навигация остальных экранов — следующий блок.
- Фото/имя Андрія из эталона не копировать в реальный профиль. При отсутствии аватара использовать настоящую первую букву имени. Числовые badge уведомлений не добавлять.

## 3. Mobile и tablet

- 390×844 и дополнительно 360px: drawer вместо sidebar, header без переполнения, безопасная нижняя область под существующую навигацию.
- Порядок: приветствие/CTA → компактный график → предметы сеткой 2×2 → план → ближайший пробник. Крупные touch-target сохраняются; поведение drawer/профиля/выхода остаётся рабочим.
- До 768px — одна колонка основных панелей; 768–1279px — сохранять место под sidebar и предметы 2×2, нижние блоки раскладывать по фактической доступной ширине. Не сжимать карточки до переполнения ради фиксированного breakpoint.
- Длинные украинские названия, имя и крупный системный текст не раздвигают viewport. Текст задачи разрешено переносить. У fixed navigation корректный safe-area, открытый drawer не находится под header.
- Изменение внешнего вида только `/` не должно поменять вывод `/admin`, `/settings`, `/tests/[id]` и других страниц до их отдельного блока.

## 4. Источники данных и честные состояния

Текущая страница — `src/app/(main)/page.tsx`, `DashboardPage`. Её серверную авторизацию и вычисления не заменять статическим JSON из коллажа.

| Область | Данные | Правило |
|---|---|---|
| Имя, год, дата | `requireUser()`, `firstName`, `examYear`, существующий `dateKey/formatUk` | Украинская подпись, согласованный серверный день; не использовать разные Date.now на сервере/клиенте. |
| Главный CTA | `todayTopic`, availability/recommendations выбранной основы | Доступный урок → `/learn/{id}`; нет доступного → `/subjects` и «Переглянути предмети». Новый ученик → «Почати перший урок», а не ложное «продовжити» пройденное. |
| Предметы | Активные `user.subjects`, соответствующие Subject и UserTopicProgress | Реальные четыре выбранных предмета. Если четвёртый биология, не подменять английским ради EN из эталона. Нет тем — подпись «Матеріали готуються», а не выдуманный процент. |
| План | Уже полученные собственные `StudyTask`, statuses, `focusDate` | 3–4 компактные строки, дальше «Увесь план». Если план начинается позже, заголовок «План на [дата]», не «сьогодні». Не показывать DONE как невыполненное и наоборот. |
| Прогресс | `ExamResult` текущего пользователя и существующие scoring helpers | Только сохранённые рейтинговые результаты, с их partial/belowThreshold/countsTowardAverage. Не преобразовывать процент/сырой тестовый балл в рейтинг. |
| Ближайший пробник | Уже полученный `nextMock` | В текущем dashboard берётся **одна** ближайшая запись. Показывать одну, если она одна; если нет — понятное empty state со ссылкой `/exams`. Не придумывать три внешних варианта из коллажа и не расширять алгоритм расписания. |

### График «Мій прогрес»

- Компактный вариант существующего `RatingChart`/Recharts; данные приходят сериализованными с server page, Prisma не импортируется в клиентский компонент.
- Стартовый ряд — общий сохранённый рейтинг: для дат результатов вычислять существующий `averageOfLatestFull` по доступным на эту дату полным результатам четырёх активных предметов. Если helper возвращает null, точка остаётся отсутствующей; не подставлять 0 и не интерполировать прошлые оценки как реальные замеры.
- Период по умолчанию — последние 30 дней; рабочий выбор 7/30/всё фильтрует уже полученные данные. Label обновляется, это не декоративный select.
- Если для общего ряда недостаточно данных — «Недостатньо даних для загального рейтингу», понятный переход `/results#add`; никаких нарисованных восходящих линий. Допустима одна точка без искусственного тренда.
- Ось рейтинга 100–200. Не копировать случайную шкалу из коллажа, если она противоречит шкале настоящего показателя.
- Сохранить helper и его тесты; новый код — чистая подготовка точек/фильтрация и presentation. Если для такой визуализации потребуется изменение формулы или новые серверные данные — вынести вопрос за пределы D01.

## 5. Контракты действий

| Элемент | Ожидаемое поведение |
|---|---|
| Логотип / «Головна» | `Link href="/"`, aria-current на текущем пункте. |
| Header search | Существующий GET `/search?q=...`; mobile search `/search`. Не рисовать неработающий shortcut. |
| «Продовжити навчання» / первый урок | Реальный разрешённый ID выбранного урока; fallback описан выше. |
| «Весь мій план» | `/curriculum?mode=personal`. |
| Карточка предмета | `/subjects/{реальный subject.id}`. |
| План: перейти к учебному материалу | `/learn/{topicId}`, только когда нужный topic действительно доступен. Для задачи без темы — рабочая ссылка на её день `/calendar?view=day&date={dateKey}`. |
| План: изменить статус/перенести | Только существующий `TaskControls` с pending/feedback; нельзя превратить всю строку в Link с вложенными button. |
| «Найближчі пробники» | Запланированная задача ведёт к её дню календаря; «Усі пробники» — `/exams`. Не путать StudyTask.id, Test.id и TestAttempt.id. |
| Профиль / тема / выход | Существующие handlers/формы. Ученик не получает admin link, владелец сохраняет свой доступ через профиль. |
| Выбор периода | Обновляет данные/подпись графика, не теряет остальные состояния страницы. |

Если у элемента нет честного источника и рабочего поведения, его нет среди активных кнопок. Внешние ссылки на будущий каталог Освіта.ua в D01 не добавлять.

## 6. Границы diff

Допускаются после подтверждения:

- `src/app/(main)/page.tsx`: композиция и чистая подготовка представления на существующих персональных данных.
- Новые визуальные `src/components/dashboard/*`: приветствие, карточки предметов/плана/пробника, компактный график. Это **предлагаемые**, ещё не существующие файлы.
- `src/components/ui.tsx`, `subject-icon.tsx`, `charts.tsx`: обратносовместимые variants, не смена контракта всех потребителей.
- `src/components/app-shell.tsx`: только ограниченный вариант оформления на `/`; существующие условные ссылки и handlers неизменны.
- `src/app/globals.css`: namespaced tokens/styles для этого варианта. Не менять все страницы глобально незаметно для владельца.
- Локальные QA-тесты и отчёт D01; новые зависимости по умолчанию не нужны.

Запрещены: `prisma/**`, `src/server/**`, `permissions.ts`, `session.ts`, оценивание/планирование/импорт материалов, собственные fake data, создание уведомлений/файловой CMS/AI/магазина. Изменение контракта требует остановки и отдельного решения, а не попутного расширения.

В текущем dashboard уже есть старый скрываемый блок XP и достижений. D01 не развивает и не выводит его в новую композицию; исторические XP-записи и серверные начисления не трогать. Полезные прежние переходы к результатам/ошибкам/повторению сохранить через существующую навигацию или компактные ссылки; не выводить большую коллекцию метрик в первый экран вопреки эталону.

## 7. Приёмка D01

### Функциональная

1. Проверить 1440×900 и 390×844: вход → `/` → предмет → доступный урок → назад → план/календарь. Reload/back/forward сохраняют сессию.
2. Кликнуть все видимые ссылки/кнопки, header search, выбор периода, профиль, тему, drawer, logout; зафиксировать URL/ответ, отсутствие тихих no-op.
3. Ученик без результатов/тем, с одним результатом, с полными результатами; отсутствие ближайшего пробника; план в будущем; длинные названия; выбранная биология вместо английского.
4. STUDENT_A не видит показатели/план B; admin controls не появляются у ученика; у OWNER/EDITOR существующий переход в свой контекст остаётся доступен без изменения прав.
5. Сетевой отказ мутации TaskControls показывает сообщение и повтор; UI не утверждает, что запись сохранена. Переход к графику не инициирует mutation.

### Визуальная

1. Dark/light × desktop/mobile; отдельно 768px с sidebar и 1920px с max-width. Сравнить порядок и пропорции с **экранами 1 и 16 оригинального 16-экранного коллажа**.
2. Карточки компактные, CTA заметен, график рядом с приветствием, четыре предмета отдельным рядом на desktop, план/пробник снизу. Нет возврата к прежней большой hero-card на полэкрана.
3. Никаких подставленных 194 баллов/70%/аватара/имени Андрія. Данные влияют на empty states, а не меняют эталонную иерархию.
4. Фокус/клавиатура/контраст/reduced motion; screen reader названия; горизонтального overflow нет; fixed-панели не перекрывают действия.
5. Сначала визуальный просмотр снимков владельцем, затем новый локальный baseline. Не обновлять старые snapshots автоматически для получения зелёного теста. Сравнение скриншота с baseline само по себе не доказывает соответствие коллажу.

### Техническая

- До запуска изучить scripts и убедиться в изоляции. Typecheck без incremental, lint без fix; релевантные pure/unit-тесты. Production build и browser acceptance — только в подготовленной QA-среде после разрешения D01, не против рабочей SQLite.
- Сопоставить до/после protected diff: схема, миграции, roles/session/server actions не изменены. UI payload не содержит секретов и полных пользователей.
- Результат D01: SHA, список файлов, снимки desktop/mobile двух тем, таблица кнопка→результат, результаты проверок и известные ограничения. Без автоматического merge/push/применения рабочей миграции.
