Срез: 21 октября 2026 года. Основная ветка `cursor/nmt-academy-lessons-and-audit`, HEAD `2169596c5b4ccb363ebf02d1692c4754a886575b`. Статус этапа отделён от наличия кода: уже реализованный компонент сам по себе не означает приёмку всего этапа.

## Статус решения

Владелец утвердил последовательность и содержание всех десяти этапов 00–09. Для этапов 02–09 отдельные детальные ТЗ будут подготовлены перед исполнением. Отсутствие этих ТЗ не отменяет утверждения дорожной карты и не даёт разрешения начинать следующий этап автоматически.

Последнее продуктовое решение по регистрации — открытая самостоятельная регистрация без обязательного приглашения. Система старых приглашений и данные сохранены, но возвращать обязательный код для публичной регистрации нельзя без нового решения владельца.

## Возможные технические подпланы

A01–A06 из `D:/НМТ Сайт/architecture/A00-2026-10-20/07-implementation-roadmap.md` остаются техническим предложением. Их можно использовать как подпланы внутри утверждённых этапов после сверки с соответствующим детальным ТЗ. Они не заменяют этапы 02–09, не меняют их порядок и не расширяют полномочия исполнителя. Привязка конкретного A-подплана к этапу требует решения в задаче этого этапа.

## Рабочие контрольные точки

1. Перед задачей проверить HEAD, Git status, принятое решение владельца и границы этапа. Описать цель, затрагиваемые файлы, ограничения, критерии готовности и целевые тесты.
2. Малые изменения проверять адресно. Полный набор проверок запускать после значимых изменений, миграций и перед выпуском. Тесты с записью выполнять только на изолированной QA-базе.
3. Рабочую SQLite, резервные копии, реальные аккаунты и сервер менять только в пределах отдельного разрешения. Перед миграцией проверять схему и данные на копии.
4. После задачи подготовить `TASK-REPORT.md` и `TASK-CHANGES.zip` только с её безопасными изменёнными документами или файлами. Коммит, merge и push — только по разрешению.
5. Завершить этап 01 ревью накопленных изменений и разрешённым владельцем Git checkpoint. Этап 02 не начинать до отдельного задания владельца.

## Отложенные задачи по утверждённым этапам

- **Этап 02 — интерфейс:** удалить поле «Рік НМТ» из интерфейса; исправить числовые поля, в которых нельзя очистить `0`; проверить аналогичные формы. Это задачи редизайна, не часть текущего auth-checkpoint.
- **Этап 03 — учебный цикл:** исправить повторное появление перенесённого задания `d2-s1` на старой дате после `syncPlan`; проверить повторную синхронизацию и загрузку учебных данных. Ошибка загрузки в Google QA была вызвана отсутствием `Subject` в пустой тестовой базе; для рабочей базы аналогичный дефект не доказан.
- **Этап 07 — публикация:** настроить production Google OAuth и подтверждённый домен Resend; ввести общий rate limiting для нескольких процессов/инстансов и провести финальный security review.

## Открытые решения

Нужны отдельные детальные ТЗ и критерии приёмки для этапов 02–09; решение владельца по Git checkpoint этапа 01; для будущей публикации — инфраструктура, домен и эксплуатационные условия. Локальный Google OAuth проверен на изолированной QA SQLite; публичный домен и production-провайдеры отдельно не проверялись. `docs/stage01-owner-setup.md` описывает открытую регистрацию и локальные настройки владельца.
